# kodo: AI пишет софт пока ты спишь

У тебя есть подписка на Cursor/ Claude Code / Codex /? . Ты платишь за неё каждый месяц. И 16 часов в сутки — пока ты спишь, ешь, живёшь — она простаивает.

kodo превращает эти мёртвые часы в рабочие. Ты пишешь спецификацию, запускаешь команду, уходишь. Утром — рабочий код с тестами и ревью.

## Как это выглядит

Реальный запуск: сборка мета-оптимизатора с 4 новыми алгоритмами и 73 тестами. 3 часа без присмотра:

```
🔍 [00:00] orchestrator → architect
           "Обследуй кодовую базу — интерфейс Solver, существующие алгоритмы"
📋 [03:04] architect — полный обзор архитектуры, нашёл 3 бага

🔧 [03:14] orchestrator → worker_smart: "Почини баги"
✅ [11:29] worker_smart: 82 раунда правок, тесты проходят

⚡ [12:36] orchestrator запускает параллельно:
           → architect:     "Проанализируй, как реализовать DE и PSO"
           → worker_fast:   "Реализуй TabuSearch и EDA"
           → worker_smart:  "Собери autosolve() — конкурентное портфолио"

🏁 [35:20] orchestrator → done()
           → tester ✅ → architect ❌ "утечка ресурсов — ProcessPool"
           ОТКЛОНЕНО → доработка → ❌ "class-variable contamination"
           ... ещё 7 раундов верификации ...

🎉 [2:59:50] tester ✅ → architect ✅
             4 новых алгоритма, autosolve() API, 73 теста
```

Три часа работы, ноль минут твоего времени. Архитектор-ревьюер поймал 9 раундов багов, которые одиночный агент пропустил бы — от утечек ресурсов до тонких граничных случаев в кроссовере.

## Зачем несколько агентов

Одиночный AI-агент плохо масштабируется на большие задачи по двум причинам.

Первая — контекст. На длинных сессиях агент теряет нить: забывает ранние решения, начинает противоречить собственной архитектуре. В kodo работа распределена по нескольким контекстным окнам — каждый агент фокусируется на своей задаче.

Вторая — проверка. Агент не может объективно ревьюить собственный код: тот же контекст, который породил ошибку, её и оценивает. В kodo архитектор получает код с нулевым контекстом из фазы разработки — он видит только результат, не намерения. Это как код-ревью от коллеги, который не участвовал в написании.

## Как устроен kodo

[kodo](https://github.com/ikamensh/kodo) — open source инструмент, где лёгкий оркестратор (Gemini Flash, доли цента) управляет командой AI-агентов через несколько циклов работы.

> *Почему Cursor, а не Claude Code? Claude Code требует API-доступ к Anthropic, что из России сопряжено с известными трудностями — оплата, VPN, блокировки. Cursor работает из коробки и доступен без танцев с бубном.*

Роли в команде:

- **Оркестратор** (Gemini Flash API) — координирует процесс, делегирует задачи, принимает решения. Почему API, а не CLI-инструмент? CLI-агенты (Cursor, Claude Code) построены решать задачи сами — они начинают писать код вместо того, чтобы координировать. API-модель остаётся в роли менеджера.
- **worker_smart** (Cursor) — сложная реализация, архитектурные задачи.
- **worker_fast** (Cursor / Gemini CLI) — быстрые задачи, итерации.
- **architect** (Cursor) — ревьюит код на соответствие требованиям.
- **tester** (Cursor) — прогоняет тесты, проверяет поведение.

Оркестратор разбивает цель на **стадии** — независимо верифицируемые куски работы. Стадии могут выполняться последовательно или параллельно в отдельных git worktree. Прогресс чекпоинтится автоматически — если прогон прервётся, его можно продолжить с `kodo --resume`.

Когда воркер заканчивает, архитектор и тестировщик проверяют результат вслепую. Нашли проблему — воркер дорабатывает. Цикл повторяется, пока все ревьюеры не примут.

## --improve: QA-аудит без формулировки цели

Фича, которой я пользуюсь чаще всего:

```bash
kodo --improve ./my-project
```

Просто указываешь на проект. Система сама проводит 4-этапный анализ:

1. **Базовый анализ** — прогоняет тесты, линтеры, тайпчекеры. Фиксирует падения и пробелы в покрытии.
2. **Happy Path** — пользуется софтом как юзер, пишет интеграционные тесты для непокрытых сценариев.
3. **Adversarial** — кидает мусорные данные, рейс-кондишены, краевые случаи.
4. **Фикс и отчёт** — чинит безопасные вещи (коммитит за тебя), а для остального генерирует markdown-отчёт с файлами и строками.

Этапы 2 и 3 идут параллельно в изолированных worktree. Возвращаешься к чистому коммиту автофиксов и списку того, что требует твоего решения.

## Большой запуск: движок по дизайн-документу

Чтобы проверить масштаб, я взял архитектурный документ на Python-движок — компоненты, физика, рендер-пайплайн — но ни строчки кода. Запустил kodo и пошёл спать.

Через шесть часов: рабочий движок. Не скелет — реальный engine, собранный, протестированный, несколько раз отклонённый архитектором и пересобранный. Одиночная сессия на такой задаче упёрлась бы в лимиты контекста где-то на середине.

## Стоимость

kodo перекладывает вычислительную работу на подписку Cursor. Единственные реальные расходы — оркестратор на Gemini Flash API.

Типичный 3-часовой ночной прогон: **~$0.10–0.15**. kodo разделяет расходы на «API» (реальные деньги за оркестратор) и «Virtual» (что подписка покрывает бесплатно), чтобы не было сюрпризов.

## Быстрый старт

```bash
# Установка
uv tool install git+https://github.com/ikamensh/kodo

# Интерактивный режим — проведёт через настройку
kodo ./my-project

# QA-аудит
kodo --improve ./my-project

# Сборка по спецификации
kodo --goal-file feature.md ./my-project

# Ночной запуск
nohup kodo --goal-file feature.md --cycles 10 --auto-refine -y ./project > run.log 2>&1 &
```

Требования: Cursor + ключ Gemini API (`GOOGLE_API_KEY`). Опционально: Gemini CLI или OpenAI Codex как быстрые бэкенды. Подробности по настройке бэкендов — в [docs/providers.md](https://github.com/ikamensh/kodo/blob/main/docs/providers.md).

## Кастомные команды

Можно настроить состав агентов через `team.json` — добавить security-аудитора, UX-ревьюера, performance-аналитика. Оркестратор видит всех агентов в команде и делегирует по необходимости.

```bash
kodo teams add my-team     # интерактивное создание
kodo teams                 # список доступных команд
kodo --team my-team ./project
```

## Бесплатный уровень

Нет подписки на Cursor? Можно запустить kodo через [Gemini CLI](https://github.com/google-gemini/gemini-cli) с бесплатным API-ключом от [Google AI Studio](https://aistudio.google.com/apikey) (без карты).

```bash
export GOOGLE_API_KEY="your-key"
uv tool install git+https://github.com/ikamensh/kodo
kodo --improve ./my-project
```

Важный нюанс: бесплатный ключ даёт доступ только к Flash. При логине через Google-аккаунт CLI иногда использует Pro, но на практике быстро откатывается на Flash из-за квот. Для `--improve` и небольших задач этого хватает. Для серьёзных ночных прогонов — скорее нет: качество ревью на Flash заметно ниже.

## Когда использовать (а когда нет)

kodo — не замена работе за клавиатурой. Если ты исследуешь, учишься или итерируешь над чем-то размытым — работай с Cursor напрямую.

kodo для другого: ты точно знаешь, что хочешь, можешь описать это в спеке — и тебе нужно исполнение. Написал спецификацию вечером, запустил `kodo`, утром — результат. Подписка работает, пока ты отдыхаешь.
